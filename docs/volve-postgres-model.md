# Модель данных Volve → PostgreSQL

Документ описывает источники в папке `xml`, спроектированную схему PostgreSQL, правила
преобразования и механизм пакетной записи (по 1000 записей).

## 2. Схема PostgreSQL

Схема создаётся EF Core миграцией `Migrations/*_InitialCreate.cs`. Все таблицы и колонки —
в `snake_case` (например, `drilling_reports.dtim_start`, `production_daily.bore_oil_vol`).
Измеряемые величины хранятся в `double precision`, даты — `date`, даты-время — `timestamptz` (UTC),
идентификаторы — `integer`/`bigint` c `GENERATED BY DEFAULT AS IDENTITY`.

## 3. Правила преобразования данных

1. **Имена.** Из `nameWell`/`nameWellbore` и имён папок удаляется префикс `NO `, `_` в префиксе
   заменяется на `/` (`15_9-F-15 A` → `15/9-F-15 A`), имя скважины получается отбрасыванием
   литеры ствола (`15/9-F-15 A` → `15/9-F-15`, `15/9-19 ST2` → `15/9-19`). Благодаря этому
   совпадают стволы из WITSML, папок траекторий и книги добычи.
2. **Папки вида `Relief well location N`.** Для проектных траекторий скважина создаётся с именем
   папки (`Relief well location 1…5`), ствол — с именем вложенной папки (`F-1 C`, `F-15 D`).
3. **Отсутствующие значения.** Сентинел `-999.99` (а также пустые строки и текст `NULL`)
   преобразуется в `NULL`.

## 4. Миграция и пакетная запись (1000 записей)

### 4.1 Схема

Миграция EF Core: `Migrations/<timestamp>_InitialCreate.cs` (+ `GeoPulseDbContextModelSnapshot.cs`).
Создаёт 23 таблицы, индексы и внешние ключи. Применение:

```powershell
dotnet tool restore                    # ставит dotnet-ef из dotnet-tools.json
dotnet ef database update              # применить миграцию вручную
```

Дополнительно миграция применяется автоматически при `Database:AutoMigrate = true`
и всегда — перед импортом (`dotnet run -- --import`).

### 4.2 Пакетная запись

Класс `GeoPulse.Data.Import.BatchWriter` накапливает изменения и вызывает `SaveChanges`
при достижении `Volve:BatchSize` (по умолчанию **1000**). Размер пакета никогда не превышается:
перед добавлением графа сущностей (отчёт + его дочерние секции) проверяется свободное место,
и при необходимости пакет закрывается досрочно. После записи `ChangeTracker` очищается,
поэтому память не растёт на 64 тыс. записей.

Дополнительно провайдер Npgsql настроен на `MaxBatchSize(1000)` — EF Core отправляет не более
1000 команд в одном `SaveChanges` (несколько `INSERT ... RETURNING` в одном сетевом обмене).

Результат прогона на полном наборе данных:

```
Импорт Volve: 63865 записей, 66 пакетов по 1000; скважин 20, стволов 54,
отчётов 1759, добыча (сут.) 15634, добыча (мес.) 526, за 24,1 с
```

### 4.3 Запуск импорта

```powershell
docker compose up -d                   # PostgreSQL 17 (geopulse/geopulse@localhost:5432)
dotnet run -- --import                 # миграция + импорт
```

или через API (Swagger — `/swagger`):

```
POST /api/import/volve                 # запустить импорт
GET  /api/import/runs                  # журнал импортов
GET  /api/wells                        # скважины из БД
GET  /api/wells/{id}/wellbores         # стволы скважины
```

### 4.4 Настройки (`appsettings.json`)

```json
"ConnectionStrings": { "GeoPulse": "Host=localhost;Port=5432;Database=geopulse;Username=geopulse;Password=geopulse" },
"Database": { "AutoMigrate": false },
"Volve": {
  "DataRoot": "xml",
  "BatchSize": 1000,
  "ImportDrillingReports": true,
  "ImportSurveyReports": true,
  "ImportProduction": true,
  "ForceReimport": false
}
```

`Volve:MaxDrillingReportFiles` (не задан по умолчанию) ограничивает число обрабатываемых
XML-файлов — удобно для быстрой проверки. Любой параметр можно переопределить переменной
окружения, например `Volve__BatchSize=500`.

## 6. Ограничения

- `EDM.XML\Volve F.edm.xml` (211 МБ) — выгрузка EDM, не импортируется: для неё нужен отдельный
  парсер EDM-схемы (`export/TOPLEVEL/...`), в текущей модели не описан.
- `StressCheck\*.sck` и `Wellcat\*.wcd` — проприетарные бинарные форматы, не читаются.
- PDF/HTML-версии суточных отчётов и survey-отчётов не импортируются (это дубли текстовых данных).
- `wellbores.name` уникально в пределах скважины, но не глобально: проектные стволы
  (`Relief well location N\F-1 C`) имеют короткие имена и не совпадают с фактическими
  `15/9-F-1 C`; фактические данные связываются по нормализованному имени.
- Массивы `uom`/`datum` не сохраняются построчно (кроме двух исключений выше) — единицы
  зафиксированы в описании колонок.

4. **Даты и время.** `dTim*` переводятся в UTC (`timestamptz`), `dateDrillComplete` и даты
   survey-отчётов — в `date`. `DATEPRD` из Excel — серийный номер (OADate) → `date`.
5. **Кодировки.** XML читается по BOM/декларации (`ISO-8859-1` по умолчанию, `Latin1` как fallback),
   недопустимые в XML 1.0 символы удаляются; текстовые отчёты — строгий UTF-8 с fallback на Latin1.
6. **Единицы измерения.** В исходных данных `uom` постоянны для каждого поля (м, дюймы, бар,
   г/см³, °C, м³/сут, ppm и т. д.) и зафиксированы в описании колонок; построчно `uom` не хранится,
   кроме даттума глубин раствора (`md_datum`) и единицы штуцера (`avg_choke_uom`).
7. **Дубликаты.** `source_file` в отчётах бурения и траекторий — уникальный ключ идемпотентности;
   при повторном импорте файл пропускается. Добыча перезаписывается целиком при
   `Volve:ForceReimport = true`, иначе пропускается, если таблицы уже заполнены.
